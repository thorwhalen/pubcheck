pubcheck#

pubcheck: one publication check for every writer.

Is this text fit for the repository it is about to be published to? A private target passes; a public (or unknown) one is scanned for names from the owner’s acquaint records, the owner’s own matters (“the operator stated”), private references, session links, credentials, and, for an unattended writer, @mentions. An unattended writer fails closed.

>>> from pubcheck import check
>>> check("Fixed the parser.", repo="octo/app", public=True, log=False).decision
'pass'

Three ways in, one check: check() in Python, public-text-guard check on the command line (exit 0 pass, 1 flag, 2 unavailable), and pubcheck.correspond:before_send as correspond’s before_send.

pubcheck.check(text, *, repo=None, title=None, more=(), unattended=False, public=None, surface='text', override=None, repo_dir=None, detectors=None, budget=None, writer='pubcheck', log=True, context=None)[source]#

Check text (and title) for publication to repo; never raises.

more are other strings published with it (labels, a category, file names, the people a post notifies as @login). public skips the visibility lookup when the caller already knows (correspond’s audience). repo_dir names a checkout whose origin is the target when repo is not given. detectors defaults by unattended. override is ignored when unattended: nobody is there to give a reason. context adds fields to the log event (a session id, a tool name), never text.

An unattended check asks GitHub for the visibility instead of trusting a cached “private” (a repo made public today must not pass unscanned), and holds a text longer than MAX_TEXT as unavailable.
