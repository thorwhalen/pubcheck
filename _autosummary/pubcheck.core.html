pubcheck.core#

The check: is this text fit for the repo it is about to be published to?

check() is the one entry point every writer calls (the Claude Code hook through the CLI, correspond’s before_send, hatchway through the CLI). It answers a Verdict:

  • pass: a private target (nothing is scanned), or nothing found;

  • flag: a detector found something; the text must not be published as is;

  • unavailable: the check could not be made. For an unattended writer (nobody reads the post before it goes out) that is a missing registry, a lookup out of time, or any error; such a writer must hold the text, never post it. An attended writer proceeds without the registry (the gap is logged), and only an error makes the check unavailable;

  • override: found something, but the author gave a reason to publish anyway (the hook’s # public-text-ok: <reason>); logged with the reason.

An unknown visibility (offline, no gh, no such repo, no repo named) is public.

>>> v = check("A neutral release note.", repo="o/r", public=True, log=False)
>>> v.decision, v.exit_code
('pass', 0)
>>> v = check("As the owner asked, we fixed it.", repo="o/r", public=True, log=False)
>>> v.decision, v.categories, v.exit_code
('flag', ['owner-relation'], 1)
>>> check("the owner asked", repo="o/r", public=False, log=False).decision
'pass'

Check text (and title) for publication to repo; never raises.

more are other strings published with it (labels, a category, file names, the people a post notifies as @login). public skips the visibility lookup when the caller already knows (correspond’s audience). repo_dir names a checkout whose origin is the target when repo is not given. detectors defaults by unattended. override is ignored when unattended: nobody is there to give a reason. context adds fields to the log event (a session id, a tool name), never text.

An unattended check asks GitHub for the visibility instead of trusting a cached “private” (a repo made public today must not pass unscanned), and holds a text longer than MAX_TEXT as unavailable.
